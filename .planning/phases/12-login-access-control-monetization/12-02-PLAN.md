## NECESSIDADES EXTREMAS

- Supabase Auth pode ser usado agora, mas o desenho deve evitar lock-in e “bomba-relógio”.
- Backend é a única fonte de verdade para autenticação, autorização, entitlement e quota (nunca confiar no frontend).
- Criar camada adapter de autenticação no backend para permitir troca futura de provedor sem reescrever regras de acesso.
- Tokens de acesso curtos + refresh rotativo + revogação imediata + trilha de auditoria.
- Sistema fail-closed: qualquer falha de auth/entitlement bloqueia acesso à análise de IA.
- Export/backup e migrações versionadas de usuários/entitlements desde o início.

  <files>backend/main.py, backend/settings.py, backend/tests/test_auth_endpoints.py, backend/tests/test_ia_access_guard.py</files>
  <behavior>
    - Case 1: POST /auth/login with valid credentials returns short-lived access token + refresh token metadata.
    - Case 2: POST /auth/refresh with valid refresh token rotates session and invalidates prior refresh token.
    - Case 3: POST /auth/logout revokes active session and subsequent access to /coaching/* returns 401.
    - Case 4: GET /coaching/{match_id} without valid session OR without active entitlement returns 403 with safe message (no sensitive internals).
    - Case 5: IA analysis path (`/local/upload` -> `_process_local_upload` -> `/coaching`) persists terminal status (ready/pending/failed) and never returns ambiguous empty success.
  </behavior>
  <implementation>Write RED tests first in `test_auth_endpoints.py` and `test_ia_access_guard.py`, then implement login/refresh/logout/me endpoints in `main.py` using server-side signing + DB-backed revocation. Add settings for token TTL/secret and enforce entitlement check before returning coaching payload or status, while preserving local-app upload auth split. Ensure all failures are explicit and logged for audit (rate-limit + auth failure context) per D-06.</implementation>
</feature>
