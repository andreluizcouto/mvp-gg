# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Phase goal: Deliver a polished match page and discovery flow that makes the improved coaching easy to use and believe.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — bare Tailwind CSS utility classes |
| Preset | not applicable |
| Component library | none (hand-written React components) |
| Icon library | inline SVG only (no icon library installed) |
| Font | Plus Jakarta Sans — variable, weights 200–800, loaded via Vite |

**shadcn gate result:** Project is React/Vite but uses no component library by deliberate design. No shadcn initialization performed. All UI is hand-crafted Tailwind. This contract continues that pattern.

---

## Spacing Scale

Declared values — Tailwind 4px-base grid. All spacing uses Tailwind utility classes (`p-N`, `gap-N`, `m-N`) mapped to the following logical tokens:

| Token | Tailwind | px | Usage |
|-------|----------|----|-------|
| xs | `gap-1`, `p-1` | 4px | Icon gaps, inline badge padding |
| sm | `gap-2`, `p-2` | 8px | Compact element spacing, cell padding in scoreboard |
| md | `gap-4`, `p-4` | 16px | Default element spacing, card internal padding |
| lg | `gap-6`, `p-6` | 24px | Section padding, between major blocks on match page |
| xl | `gap-8`, `py-8` | 32px | Layout gaps, page top/bottom padding |
| 2xl | `py-12` | 48px | Major section breaks (home hero) |
| 3xl | `py-16` | 64px | Page-level spacing on SearchScreen |

**Exceptions:**
- Navbar height is fixed at `h-[50px]` — not on the 8-point scale, preserved from existing implementation.
- Scoreboard column grid uses `gap-1.5` (6px) and `gap-2` (8px) — kept dense per D-10.
- Touch-target minimum for interactive elements: 32px height (`h-8`) in scoreboard rows; 44px (`h-11`) for primary CTAs.
- Status badge height: `h-[48px]` for ScoreBadge — preserved from existing implementation.

## Typography

All sizes are declared in `tailwind.config.js` as custom tokens. Use only these tokens — do NOT use arbitrary `text-[Npx]` values for new elements.

| Role | Tailwind Token | Size | Weight | Line Height | Usage |
|------|---------------|------|--------|-------------|-------|
| Display | `text-hxl` | 32px | 700 | 1.1 | Hero heading on SearchScreen only |
| Heading | `text-hxs` | 20px | 700 | 1.2 | Section headings (e.g. "Coaching IA" section label) |
| Body | `text-body` | 16px | 500 | 1.5 | Card titles, coaching status primary text, match result, champion name, KDA values, match meta, tab labels, nav links |
| Label | `text-label` | 11px | 500 | 1.5 | Column headers in scoreboard, badges, timestamps, helper text, status block copy, validation errors |

**Declared font weights:** 500 (`font-medium`), 700 (`font-bold`). Weight modifiers override the base 500 on specific elements.

**Scoreboard exception:** Column data uses inline `text-[10px]`, `text-[9px]` to preserve existing dense D-10 layout. These are justified inline exceptions — NOT scale entries. Do not normalize in Phase 4.

**Coaching text:** Body copy inside `UnlockedCoaching` uses `text-[13px] leading-[1.75]` — preserve this for readability, no change needed.

**Disabled tab labels:** Use `text-label` weight 500 at `text-black-500` color. Append "Em breve" tooltip text via `title` attribute.

## Layout Contract — Match Page (ResultsScreen)

**Above-the-fold order (D-09):** The following blocks appear in this exact vertical sequence:

```
[ Back button ]
[ Match header card ]         ← champion icon, result, KDA, items, score badge
[ Analysis status block ]     ← D-12: short "Status da análise" with state + reason
[ Coaching IA block ]         ← CoachingSection (ready / pending / failed / private)
─────────────────────────────── fold line on most viewports ────────────────────────
[ Scoreboard section ]        ← InlineScoreboard, tabs below
```

Scoreboard is intentionally below the fold. Do NOT move it above coaching.

**Primary visual focal point:** The Coaching IA block. All other above-the-fold elements support scanning toward it.

**Back button behavior (D-02):**
- If `window.history.length <= 2` OR `!location.state?.from`, navigate to `/` (home).
- Otherwise: `navigate(-1)`.
- Implementation note: Pass `{ state: { from: location.pathname } }` on all `navigate('/match/:id')` calls from `SummonerProfileScreen` to enable this check.

**Back button visual spec:**
- Label: `← Voltar` (left arrow character + space + "Voltar")
- Accessibility: `aria-label="Voltar para a home"` on the `<button>` element
- Styles: `text-label text-black-300 hover:text-black-100 font-medium transition-colors flex items-center gap-1`
- Position: top-left, `mb-3` below navbar, before match header card

**Match page max-width:** `max-w-5xl mx-auto px-4 py-6` — preserve existing.

**Scoreboard density (D-10):** No mobile simplification. `overflow-x-auto` wrapper with `min-w-[900px]` inner div is the correct pattern. Keep all columns visible at all viewports.

## Component Interaction Contracts

### Disabled Tabs — "Detalhes" and "Runas" (D-11)

**Visual state:**
- Text color: `text-black-500` (NOT `text-black-400`)
- No bottom border — remove any active-tab indicator
- Cursor: `cursor-not-allowed`
- No hover state change

**Label format:** `{tab.label}` with appended suffix using `title` attribute:
```jsx
<button
  disabled
  title={`${tab.label} — Em breve`}
  className="pb-3 text-label font-medium text-black-500 cursor-not-allowed"
>
  {tab.label}
  <span className="ml-1.5 text-[9px] text-black-500 font-medium tracking-wide">Em breve</span>
</button>
```

The "Em breve" suffix is rendered inline as a `<span>` — NOT a tooltip-only implementation. It must be visible at all times on the label.

**Interaction:** `onClick` must be suppressed (disabled button). No navigation, no tab content swap.

### IA Badge on Match List (D-05)

**Show only when:** `coaching_status === "ready"` from `fetchCoachingStatus` response.
**Do NOT show when:** `pending`, `failed`, `unavailable`, or status is missing/null.

**Visual:**
```jsx
<span className="text-[9px] font-bold text-gold-400 bg-gold-400/15 px-1.5 py-0.5 rounded">
  IA
</span>
```

### Match Load Error (D-04)

Replace the current single-line error text with an inline error block:

```
[ ⚠ icon ] Partida não encontrada ou erro ao carregar.
            [ Tentar novamente ]  [ Ir para home ]
```

**Visual spec:**
- Container: `max-w-2xl mx-auto px-4 py-10 text-center`
- Icon: inline SVG warning triangle, `w-8 h-8 text-red-500 mx-auto mb-3`
- Message: `text-label text-black-300`
- "Tentar novamente" button: `bg-black-700 border border-black-500 text-black-100 text-label font-bold px-4 py-2 rounded-md hover:bg-black-600 transition-colors`
- "Ir para home" button: `text-blue-400 text-label font-bold hover:underline transition-colors`
- Buttons: inline-flex row, `gap-3`, centered

- **No download CTA** — this is a permissions state, not an upsell state.

## Analysis Status Block (D-12)

New component to be added **between** the match header card and the coaching block.

**Purpose:** Short, explicit trust signal showing the current coaching state + a friendly reason. Reduces confusion about whether AI coaching is available.

**Position:** `mt-3 mb-3` between match header and coaching section.

**Visual spec:**
```
[ status dot ]  Estado da análise: {state_label}  —  {reason_text}
```

- Container: `flex items-center gap-2 px-3 py-2 rounded-lg bg-black-800/60 border border-white/5`
- Status dot: `w-1.5 h-1.5 rounded-full flex-shrink-0` — color per state (see color table above)
- Label prefix: `text-label text-black-400 font-medium uppercase tracking-wider`
- State label: `text-label text-black-200 font-bold`
- Separator: `text-label text-black-500` — ` — ` (en-dash with spaces)
- Reason: `text-label text-black-400`

**State → label → reason mapping:**

| Status | Dot Color | State Label | Reason |
|--------|-----------|-------------|--------|
| `ready` | `green-600` | Análise pronta | Coaching disponível para esta partida |
| `pending` | `yellow-400` | Análise em andamento | Aguarde alguns instantes e recarregue |
| `failed` | `red-500` | Análise falhou | Não foi possível processar esta partida |
| `unavailable` (no evidence) | `black-400` | Coach indisponível | Baixe o app e jogue uma partida |
| `private` (shared link) | `black-400` | Análise privada | Disponível apenas para o dono da conta |
| `unknown` / null | `black-500` | Status desconhecido | Não foi possível verificar a análise |

**Pending animation:** When `pending`, apply `animate-pulse-dot` to the yellow dot only.

## Search Validation Contract (D-03)

### Home Search (`SearchScreen`) — Strong Validation

All error messages are already implemented. Preserve exactly:

| Condition | Error Copy |
|-----------|------------|
| Empty input | `Digite Nick#TAG para buscar.` |
| No `#` in input | `Use o formato Nick#TAG — ex: Faker#BR1` |
| Nick or TAG empty after split | `Nick ou TAG inválidos.` |

**Error presentation:** `text-label text-accent-red` below the input. Fades out after 2s (existing `fading` state). No toast. No modal.

### Navbar Search (`Navbar`) — Minimal Validation

Current behavior: skip if empty, skip if no `#` before char 1, skip if nick/tag empty after split. Navigate immediately on valid format.

**Do NOT add:**
- Red error messages in the navbar
- Toast notifications
- Validation blocking on partial match

**Delegate downstream:** Invalid summoner names resolve to a not-found state on `SummonerProfileScreen`. The navbar is not responsible for API-level errors.

## Animation Contract

Preserve all existing animations from `tailwind.config.js`. Do not add new keyframes in Phase 4.

| Animation | Class | Usage |
