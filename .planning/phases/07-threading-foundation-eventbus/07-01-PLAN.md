After draining, re-schedule: `if self._app: self._app.after(self.POLL_INTERVAL_MS, self._poll)`.

    **Modify `backend/app_config.py`** — add thread-safety while preserving the existing API:

    1. Add `import threading` to imports (line 4 area, after `import json`)

    2. Add module-level lock after `_DEFAULTS` dict:
       ```python
       _config_lock = threading.RLock()
       ```

    3. Wrap `get_config()` body with `with _config_lock:` — indent the entire function body one level under the context manager. The function signature stays the same: `def get_config(config_dir: str | None = None) -> dict:`.

    4. Wrap `save_config()` body with `with _config_lock:` — same approach. Signature stays: `def save_config(cfg: dict, config_dir: str | None = None) -> None:`.

    5. Add new function `update_config()` after `save_config()`:
       ```python
       def update_config(key: str, value, config_dir: str | None = None) -> dict:
           """Thread-safe atomic read-modify-write. Returns updated config."""
           with _config_lock:
               cfg = get_config(config_dir)
               cfg[key] = value
               save_config(cfg, config_dir)
               return cfg
       ```
       Note: This works because `_config_lock` is an RLock (re-entrant) — `get_config` and `save_config` also acquire it, but RLock allows the same thread to acquire multiple times.
